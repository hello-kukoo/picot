## 三个问题的结论

### 1. 原生 MCP：配置文件与适配器退役

**原生配置文件（v0.99.2 `docs/mcp.md`）：**

- 用户级：`~/.pi/agent/mcp.json`
- 项目级：`.pi/mcp.json`（需 project trust 后才读取；项目条目覆盖用户级同名条目）
- 格式：标准 `{ "mcpServers": { … } }`（与 Claude Desktop/Code、Cursor 同形）。stdio 用 `command/args/env/cwd`；HTTP 用 `url/headers/oauth`；通用字段 `timeout`、`enabled: false`、`exposure`/`toolExposure`、`description`。
- 管理：会话内 `/mcp`；shell 端 `pi mcp add|remove|list|login|logout`（shell 命令不加载扩展）。扩展可经 `pi.registerMcpServer(name, config)` 注册会话级服务器。

**pi-mcp-adapter 卸载判定：卸载，正确。** 但迁移有真实坑：

- 适配器写的 `mcp-adapter.json`（全局 `<agentDir>/mcp-adapter.json` + 项目 `.pi/mcp-adapter.json`）原生 pi **不读**，卸载后条目静默消失。
- 适配器还合并四个共享文件（`~/.config/mcp/mcp.json`、`~/.agents/mcp.json`、`~/.agents/mcp/mcp.json`、项目 `.mcp.json`）——原生 pi **完全不读这些文件**。依赖它们的用户迁移后有行为损失，必须知情。
- 字段映射是**有损的**：`disabled: true` → `enabled: false`；`directTools` → `exposure: "direct"`；`inheritEnv`、`lifecycle` 无原生等价物。

**军师裁定：不做静默自动迁移。** 沿用仓库已有的一次性迁移模式（`mcp-settings.ts:154-198` 处理过 pre-3.0 `mcp.json`→`mcp-adapter.json`）：检测 → 用户确认 → 带字段映射迁移 → 对 `inheritEnv`/`lifecycle` 等有损字段显式告警。写入直接操作 `mcp.json`（schema 已文档化且稳定），不要从扩展里嵌套 spawn `pi mcp` CLI。

### 2. codemode：Picot 加开关，机制已有现成挂点

- `codemode` 由内置扩展 `builtin:codemode` 注册，默认 **inactive**（即 disable）。
- 打开：settings.json 里 `defaultTools: ["+codemode"]`（`+name` 语法是 0.99.0 新增）；或单次 `--tools read,bash,edit,write,codemode`（注意 `--tools` 是**整体替换**、不接受 `+/-`）。
- 配套设置：`codemode.mode`（`on`/`only`，默认 on）、`codemode.inlineBudget`（默认 3000）。0.99.2 起 `/reload` 能启用 defaultTools 新增的工具。

**军师裁定（两轮意见冲突后裁定）：加开关。** 第二轮军师曾以 YAGNI 主张 defer；reconcile 后维持「加」，理由：Dr. Lin 明示了该需求；实现成本低（`host_models.rs:26,35` 已有 settings.json 读写，`host_config.rs` 已有锁语义，增量是一个 host RPC + 设置页一项）；「MCP 用户自动激活 codemode」只覆盖默认 exposure 场景，盖不住 codemode-without-MCP（并行工具调用、输出过滤、Jev 分类）与 `exposure: "hidden"` 工作区。实现：加一个小 host RPC 做 `defaultTools` 的**合并式**修改（读旧值 → 无则追加 `"+codemode"`，关则移除该 token；绝不整体替换数组）。作用域默认**项目级 `.pi/settings.json`**（Picot 以 workspace 为主），全局级兜底。Picot 真实 spawn 不传 `--tools`，settings.json 对每个新会话生效，路径通。

### 3. OpenAI Codex OAuth：现状不坏，新登录方式另立项

- Picot 的设备码登录走 `ModelRuntime.login("openai-codex", …)`——该 API 在 0.99.2 未变，`packages/ai/src/auth/oauth/openai-codex.ts` 的设备码流完整保留（`device_code` 登录方式仍在）。**现有用户零改动可用。**
- 变化是「格局」而非「接口」：provider 显示名改为 "OpenAI Codex (legacy)"（id 仍 `openai-codex`，仍可登录）；新旗舰是 OpenAI provider 上的 **Sign in with ChatGPT**（`/login openai`，用 ChatGPT 订阅）。
- 新 ChatGPT 登录是 **PKCE 浏览器流**，要求全局 settings 里有 `deviceId` UUID，`openai-chatgpt.ts` **无 `device_code` 选项**——Picot 现有设备码适配层驱动不了它。
- 0.99.1 修过 bundled release 里 `/login openai` 缺 `openai-chatgpt.js` 模块的 bug——升级后如果手动试新登录，先确认拿到的是 0.99.2。

**军师裁定：本次升级不动 oauth 代码；ChatGPT 订阅登录（需 WebView 浏览器窗或粘贴回调 URL + 写 deviceId）作为独立后续项，等 Dr. Lin 决定要不要。**
