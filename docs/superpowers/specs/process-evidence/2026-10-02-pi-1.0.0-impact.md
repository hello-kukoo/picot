## 结论：零 hard break、零 soft break

1.0.0 是里程碑版本但 Picot 面**全部兼容**。逐项判定：

| 1.0.0 变更 | Picot 触及 | 判定 |
| --- | --- | --- |
| TUI 默认全屏（`tuiMode: "regular"` 可退回） | 否——Picot 走 RPC/JSON 模式，git runner 走 --print，均非 TUI。终端面板（terminal_manager.rs:584 spawn_pty）spawn 的是用户 shell，用户在面板里手敲 `pi` 会看到新全屏 TUI——属 pi 自身 UX，按设计继承 | none |
| codemode 描述瘦身 ~40% prompt token、错误自愈提示 | 否——Picot 不解析 codemode 描述；用户会话直接受益（token 下降） | 正向继承 |
| `typeof tools.name` → `"name" in tools` | 用户脚本层 breaking，非 Picot 代码 | none |
| codemode `models.generateImages()`（含 `ctx.modelRegistry.generateImages()` 扩展 API） | 新增 API，无移除；Picot 未用 | observe |
| Radius 一键登录 + 自动写 mcp.json `"auth":{"provider":"radius"}` | TUI /login 流；Picot oauth 适配层仅 openai-codex 设备码，不触及 | none |
| Anthropic copy-code 登录（headless） | 同上，TUI 流 | none |
| MCP OAuth 凭据按 server 名+URL 存储（mcp-auth.json 迁移由 pi 内部完成）；step-up sign-in 保留已授权 scope；`oauth.authServerMetadataUrl` | Picot 不读写 mcp-auth.json；mcp.json 的新 oauth 子键见上表软缺口 | none |
| `--provider` 无 `--model` 由静默忽略改为报错 | Picot 不传该 flag（grep 证实 extensions/ 与 src-tauri/ 均无） | none |
| deferred MCP 工具 resume//reload 后丢失的修复 | Picot 用户继承修复 | 正向 |
| quietStartup "header" | TUI 设置键，新键；Picot 原始 JSON 编辑器透传 | none |
